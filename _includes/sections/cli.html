Command line

Tapes without writing code

The monorepo also builds a standalone servirtium CLI — a single self-contained binary with the whole engine linked in. No language binding, no shared library, no runtime: a committed tape becomes a live stub server with one command, and tapes can be linted and converted from the shell or a CI step.

shell 
# replay a committed tape as a live stub server — zero code
servirtium serve tapes/checkout_flow.md 8080
curl http://127.0.0.1:8080/api/basket
 
# several tapes, comma-separated, served as one
servirtium serve tapes/basket.md,tapes/payment.md 8080
 
# lint every tape in a pre-commit hook or CI (exit 0/1)
servirtium check --canonical tapes/*.md
 
# capture in Chrome DevTools, convert once, replay forever
servirtium import capture.har tapes/from_browser.md

serve <tape.md>[,more.md…] [port]

Replays a tape — or a comma-separated list, concatenated — as a live HTTP server. Point a frontend dev server at it, curl it, demo against it. By default replay is repeatable and order-independent (a stub-server-style lookup that never exhausts); --ordered switches to the strict test semantics — the recorded conversation, in order, each interaction consumed once.

check [--canonical] <tape.md> …

Lints tapes: exits 0 only if every file parses as valid Servirtium markdown — made for pre-commit hooks and CI gates. --canonical additionally requires the engine emitter's exact byte-form, so golden tapes stay diff-stable across re-records.

import / export (HAR bridge)

Converts an HTTP Archive capture — Chrome DevTools, Fiddler, Charles, mitmproxy, Postman — into a Servirtium tape, and back. Capture real traffic you can't easily proxy (a browser SPA, a mobile app), convert the .har once, then replay it deterministically under any binding or serve.

one static binary

The CLI statically links the same pure-Aether engine the seventeen bindings share — same parser, same matcher, same emitter — so what serve replays and what check accepts is exactly what your tests see. Built by the monorepo's one-command bootstrap.sh alongside the engine.
